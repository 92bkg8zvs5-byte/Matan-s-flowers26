# flowers – מנוי פרחים שבועי

אפליקציית ווב מלאה ועצמאית: לקוחות נרשמים, בוחרים פרחים וכתובת לכל שבוע, משלמים בביט ועוקבים אחרי ההזמנה.
עמוד ניהול ב־`/admin` עם שם משתמש וסיסמה. אין תלות ב־Claude או בכל שירות חיצוני, ואין צורך ב־`npm install`.

## הרצה במחשב
```
node server.js
```
(דורש Node 18 ומעלה.) האתר ב־http://localhost:3000 והניהול ב־http://localhost:3000/admin.
בהרצה הראשונה מודפסים בטרמינל שם המשתמש והסיסמה של המנהל. כדי לקבוע אותם מראש: `ADMIN_USER` ו־`ADMIN_PASS`.

## העלאה לאינטרנט (Render / Railway / Fly.io / שרת VPS)
1. העלו את התיקייה ל־GitHub וחברו ל־Render כ־Web Service (Start command: `node server.js`).
2. **חשוב:** הוסיפו Persistent Disk (למשל ב־`/data`) והגדירו `DATA_DIR=/data`. בלי זה הנתונים יימחקו בכל פריסה.
3. הגדירו משתני סביבה לפי `.env.example` (לפחות `ADMIN_USER` ו־`ADMIN_PASS`).
4. חברו דומיין משלכם. HTTPS נדרש כדי שהאפליקציה תהיה ניתנת להתקנה בטלפון.

Docker: `docker build -t flowers .` ואז `docker run -p 3000:3000 -v flowers-data:/data -e ADMIN_PASS=... flowers`

## איך הלקוחות מקבלים את זה כאפליקציה (בלי הכיתוב של Claude)
כשהאפליקציה מאוחסנת בכתובת משלכם (למשל `https://flowers.co.il`), היא נפתחת כאתר רגיל, בלי שום כיתוב של Claude.
- **שליחה ללקוחות:** שולחים את הכתובת בוואטסאפ או מדפיסים ממנה קוד QR.
- **התקנה:** באייפון: Safari ← שיתוף ← "הוספה למסך הבית". באנדרואיד: Chrome ← "התקנת אפליקציה". היא נפתחת במסך מלא עם האייקון שלכם.
- **חנויות האפליקציות (אופציונלי):** אפשר לארוז את האתר כאפליקציה לחנות באמצעות pwabuilder.com או Capacitor. דרוש חשבון מפתח (Google Play כ־25$ חד־פעמי, Apple כ־99$ לשנה) ותהליך אישור של החנות. בדרך כלל ההתקנה מהדפדפן מספיקה.

## מה כבר עובד
- הרשמה וכניסה: הלקוח נשאר מחובר במכשיר שנה. כניסה ממכשיר אחר היא עם טלפון ומייל.
- בחירת פרחים וכתובת לכל שבוע, מעקב בארבעה שלבים וכפתור "קיבלתי את הפרחים".
- עמוד ניהול: הזמינו, ממתינים לתשלום, שילמו, קיבלו. עריכה, מחיקה, הוספה ידנית, שינוי שם משתמש וסיסמה.
- ביטול הזמנה על ידי הלקוח עד שלושה ימים לפני המשלוח. ביטול אחרי תשלום מסומן אצלכם "יש להחזיר ₪80", ואחרי ההחזר לוחצים "סימון: הוחזר".
- כרטיס השבוע עובר אוטומטית לשבוע הבא כשההזמנה נמסרה, בוטלה או שהתאריך עבר.
- היסטוריית הזמנות ללקוח: כמה זרים קיבל וכמה שילם.
- איור לכל פרח וקישור לתמונות בגוגל.
- במסך הניהול כל שינוי מוצג מיד (העברת סטטוס, מחיקה בשני שלבים, עריכה, הוספה ידנית).
- תזכורת שבועית ליומן: Google, ובאייפון קישור שפותח ישר "הוספה ליומן" (`/reminder.ics`).
- התקנה בטלפון (PWA).
- הנתונים נשמרים ב־`data/db.json`. **גבו אותו** באופן קבוע.

## מייל ו־SMS (אופציונלי, דורש חשבון בשירות חיצוני)
- מייל ללקוח בהרשמה ובאישור תשלום: resend.com, והגדרת `RESEND_API_KEY` ו־`MAIL_FROM`.
- SMS אליכם כשלקוח מדווח ששילם: twilio.com, והגדרת `TWILIO_SID`, `TWILIO_TOKEN`, `TWILIO_FROM`, `ADMIN_PHONE`.
- בלי ההגדרות האלה ההודעות רק נכתבות ללוג של השרת.

## מגבלות שחשוב להכיר
- **ביט:** אין ממשק ציבורי שמאשר תשלום אוטומטית. הלקוח לוחץ "שלחתי את התשלום", אתם מקבלים התראה, בודקים בביט שהכסף הגיע עם קוד ההזמנה, ומאשרים בעמוד הניהול. לאישור אוטומטי צריך סליקה עם API (כמו PayPlus, Tranzila, Meshulam).
- כניסת לקוחות בטלפון ומייל היא הגנה בסיסית. לחיזוק אפשר להוסיף קוד חד־פעמי ב־SMS.
- אחסון בקובץ JSON מתאים לעשרות עד מאות לקוחות. מעבר לזה כדאי SQLite או Postgres.
- אתם אוספים פרטים אישיים, ולכן מומלץ להוסיף מדיניות פרטיות ותנאי שימוש.
